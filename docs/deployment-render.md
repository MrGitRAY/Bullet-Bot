# استقرار Bullet Bot روی Render

این پروژه به‌صورت **Background Worker** اجرا می‌شود و برای نگهداری دیتابیس SQLite از
یک دیسک دائمی استفاده می‌کند. در محیط ابری نیازی به `TELEGRAM_PROXY_URL` نیست.

## ساخت سرویس

1. در Render یک Blueprint جدید از مخزن `MrGitRAY/Bullet-Bot` بسازید.
2. برنچ `feature/task-management` را انتخاب کنید؛ فایل `render.yaml` روی همین برنچ است.
3. هنگام ساخت Blueprint مقدار متغیرهای زیر را وارد کنید:
   - `BOT_TOKEN`: توکن دریافت‌شده از BotFather
   - `ALLOWED_USER_IDS`: شناسه عددی کاربران مجاز با قالب JSON، برای نمونه
     `[123456789]`. مقدار `[]` دسترسی را برای همه باز می‌گذارد.
4. تغییرات Blueprint را تأیید کنید. Render تصویر Docker را می‌سازد، migrationهای
   Alembic را اجرا می‌کند و سپس polling بات را شروع می‌کند.

دیتابیس در `/app/data/bullet.db` ذخیره می‌شود. این مسیر به دیسک دائمی یک گیگابایتی
متصل است و با deployهای بعدی پاک نمی‌شود.

## بررسی اجرا

در صفحه Worker، لاگ‌ها را باز کنید. پس از اجرای موفق باید پیام شروع polling دیده شود.
سپس در تلگرام دستور `/start` را برای بات بفرستید.

هم‌زمان فقط یک نمونه از بات را اجرا کنید. پیش از فعال‌کردن Worker، اجرای محلی را
متوقف کنید تا Telegram خطای `Conflict: terminated by other getUpdates request` ندهد.

هر push بعدی روی برنچ متصل به Render به‌صورت خودکار نسخه تازه را deploy می‌کند.
